# Docker Compose
Welcome to the docker compose source files!

# strategy
The [local-compose.yml](./local-compose.yml) file is used to handle all the containers on the local machine. This is used to run and test the system locally.

The [dev-compose.yml](./dev-compose.yml) file is used to install updated images to the server on the servers side and allows us (the developers) to test the system on the server side.

The [prod-compose.yml](./prod-compose.yml) file is used to run the containers in production mode on the server which will then be avaliable to the public.

# Installing the Local Development Certificate

## Why is this required?

Our Outlook Add-in is served over **HTTPS** because Microsoft Outlook requires add-in resources to be loaded from a trusted HTTPS endpoint.

For local development, we use **Caddy** to generate a local development Certificate Authority (CA) and issue HTTPS certificates.

Windows does not trust this CA by default, so each developer must install the provided `root.crt` certificate once.

> **Important**
>
> This certificate is **only** intended for local development.
> It must **never** be used in production.

---

# Before You Begin

You should have received the following file:

```
root.crt
```

Do **not** ask for or distribute:

```
root.key
```

The private key must remain private.

---

# Installing the Certificate

## Windows

### Step 1

Locate the provided:

```
root.crt
```

### Step 2

Double-click the certificate.

You should see the Certificate window.

Click:

```
Install Certificate...
```

---

### Step 3

Choose:

```
Local Machine
```

If prompted by User Account Control (UAC), click **Yes**.

> If you do not have administrator privileges, you can choose **Current User** instead.

---

### Step 4

Select:

```
Place all certificates in the following store
```

Click:

```
Browse...
```

Choose:

```
Trusted Root Certification Authorities
```

Click:

```
OK
```

---

### Step 5

Click:

```
Next
```

Then:

```
Finish
```

Windows should display:

```
The import was successful.
```

---

# Verify the Installation

Open:

```
https://localhost
```

You should **not** receive any certificate warnings.

If the site loads normally, the certificate has been installed successfully.

---

# Outlook Verification

After installing the certificate:

- Restart Outlook if it was already open.
- Sideload the Outlook add-in manifest (if required).
- Open the add-in.

The add-in should load without HTTPS certificate errors.

---

# Removing the Certificate

If you ever want to remove the development certificate:

1. Press **Win + R**
2. Run:

```
certmgr.msc
```

(or `certlm.msc` if installed for the Local Machine)

Navigate to:

```
Trusted Root Certification Authorities
    └── Certificates
```

Locate the development certificate and delete it.

# Troubleshooting

## I still receive a certificate warning

Try the following:

1. Close Outlook completely.
2. Restart your web browser.
3. Restart Docker Compose.
4. Verify that Caddy is running.
5. Ensure the certificate was installed into **Trusted Root Certification Authorities**.

---

## The add-in still won't load

Verify that the add-in is being served from the expected HTTPS URL, for example:

```
https://localhost/addin/taskpane.html
```

The page should load successfully in a browser before attempting to use it in Outlook.
