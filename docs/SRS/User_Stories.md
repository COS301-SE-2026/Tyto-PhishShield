## User stories acceptance criteria and definition of done 

| Use Case ID | User Story                                                                                                                                                                                        | Acceptance Criteria                                                                                                                | Definition of Done                                                                                                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **UC-01**   | As an employee, I want to report a suspicious email with a single click in the Outlook ribbon, so that I can earn XP on a correct report.                                                         | Email is in the inbox.<br>User clicks the report button.                                                                           | Test cases pass.<br>Code is reviewed.<br>User sees a notification.                                                                                                                                                  |
| **UC-02**   | As an employee I want to receive immediate, specific feedback when I fail to identify a phishing email or message so that I can be educated appropriately and my XP is adjusted accordingly.      | The email is in the inbox. <br>User receives a real email and reports it, or user interacts with a phishing email from the system. | Test cases pass.<br>Code is reviewed.<br>A pop-message appears with a link to the website to view the report.<br> Or the user is redirected to the website to a page that shows why the email was a phishing email. |
| **UC-03**   | As a user, I want to view a real-time leaderboard showing my XP and team rankings, so that I stay motivated to accurately identify phishing emails.                                               | User has an account.<br>The user is logged in.<br>The user clicks on the leaderboard page.                                         | Test cases pass.<br>Code is reviewed.<br>Leaderboard is displayed with various statistics shown.                                                                                                                    |
| **UC-04**   | As a new user, I want to register for an account securely, so that I can be part of the phishing platform and start tracking my progress.                                                         | User is on the registration page.<br>User submits registration details.<br>User can now log in.                                    | Test cases pass.<br>Code is reviewed.<br>Account is created in the database.                                                                                                                                        |
| **UC-05**   | As a registered user, I want to log in securely, so that I can access my dashboard and role-specific features.                                                                                    | User is registered already.<br>User submits log in details.<br>User is redirected to the main page.                                | Test cases pass.<br>Code is reviewed.<br>User can visually see that they are logged in.                                                                                                                             |
| **UC-06**   | As an Admin, I want to configure campaign parameters such as target group, schedule and difficulty, so that the AI-generated phishing campaigns are tailored and executed at the scheduled times. | User is an admin user.<br>User can submit campaign parameters in the frontend.                                                     | Test cases pass.<br>Code is reviewed.<br>User is notified that the campaign is scheduled.                                                                                                                           |
| **UC-07**   | As an Admin or Analyst, I want to view aggregated organizational metrics, so that I can identify common failure points and track the company's overall security posture.                          | User is an Admin or Analyst on the system.<br>User clicks the analytics page.                                                      | Test cases pass.<br>Code is reviewed.<br>Specific interaction logs are viewable of each user.<br>Summaries of campaigns are viewable.                                                                               |
| **UC-08**   | As an Admin, I want to configure the difficulty level and context of AI-generated campaigns, so that the simulations match the evolving skill levels of our employees.                            | User is an Admin on the system.<br>User fills in a form for generating a campaign.                                                 | Test cases pass.<br>Code is reviewed.<br>Campaign emails are sent according to required difficulty.                                                                                                                 |
| **UC-09**   | As an Admin, I want to assign roles (Admin, Analyst, User) for registered accounts, so that I can control what each person can access within the platform.                                        | User is an Admin on the system.<br>User is interacting with an accounts page.                                                      | Test cases pass.<br>Code is reviewed.<br>All accounts are displayed to the user.<br>The user can successfully edit user roles.                                                                                      |
| **UC-10**   | As the system, I want to automatically deliver AI-generated phishing emails to targeted user groups at the scheduled times, so that employees are tested without manual intervention.             | The system has phishing emails it can send.<br>The scheduled time is reached.                                                      | Test cases pass.<br>Code is reviewed.<br>The emails are received by the targeted user groups.                                                                                                                       |
| **UC-11**   | As a user, I want to view my personal XP, progress history, and past campaign results, so that I can track my own improvement over time.                                                          | User has an account on the system.<br>                                                                                             | Test cases pass.<br>Code is reviewed.<br>User cam view XP points and their own logs of their interactions with the system.                                                                                          |
| **UC-12**   | As the system, I want to automatically redact sensitive information from email content before sending it to external LLM APIs, so that POPIA/GDPR compliance is maintained.                       |                                                                                                                                    | Test cases pass.<br>Code is reviewed.                                                                                                                                                                               |
| **UC-13**   | As a user, I want my XP to be automatically updated after I report a phishing email or fall for a simulation, so that my score accurately reflects my performance.                                | The user interacts with a phishing email.                                                                                          | Test cases pass.<br>Code is reviewed.<br>XP is updated and displayed to the user in the frontend.                                                                                                                   |
| UC-14       | As an admin, I want to be able to add the users in my company to the system, so that they can easily access the system under my company.                                                          | User is an admin on the system.<br>User has access to an accounts page.                                                            | Test cases pass.<br>Code is reviewed.<br>User can successfully create an account for another user.<br>An email is sent to the new account created containing a link for the new user to update their password.      |
| UC-15       | As an admin, I want to be able to create educational material for users manually or automatically with the AI engine.                                                                             |                                                                                                                                    | Test cases pass.<br>Code is reviewed.                                                                                                                                                                               |
